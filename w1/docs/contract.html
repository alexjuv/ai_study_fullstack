API 契约与边界

这些图描述当前单进程教学服务。适配器、校验器与观测模块均在同一个 FastAPI 应用中，是逻辑职责，不是独立部署服务。

入口与请求

接口行为
POST /generatemessages 与 prompt 必须且只能提供一个；禁止额外字段。messages 最多 100 条，角色为 system / user / assistant，单条内容 1–100000 字符。max_tokens 为 1–16384，默认 1024。

GET /metrics当前进程内最近 100 条调用记录；不从 JSONL 回读，重启清空内存记录。

结构化输出与 SSE

response_format 为 json_object 或 json_schema。后者必须带 name 和 schema；只允许以 # 开头的本地 $ref / $dynamicRef。输入时检查 schema；输出时使用无远程检索能力的 Registry 验证。结构化请求还会在消息前注入 schema 的 system 提示。

上游总是 stream=true，包括下游 stream=false。解析器按空行分帧，支持 CRLF、多行 data，忽略注释及非 data 行；忽略 [DONE]，但仍要求协议自己的完成事件。未闭合帧、非法 JSON、无完成事件与空输出分别报错。

普通流式响应逐块发送 event: delta，结束发 event: done。结构化响应在完整文本通过 JSON 与 schema 校验之后才发送一个完整 delta，再发 done；因此首个可见块会晚于 metrics.ttft_ms。done.text 已包含完整文本，客户端不能再把它当增量追加。

限流与重试生命周期

顺序：字段验证 → 模型选择 → 模板展开 / schema 提示 → 密钥检查 → 每模型滑动窗口 → open_upstream → 消费 SSE → 关闭响应 → record。窗口仅驻留当前进程，默认每模型每 60 秒 20 次；成功准入就占一格，后续失败不退还；上游内部重试不额外占格。没有 Redis、共享配额或后台任务队列。

初始请求 + 最多 3 次重试，共最多 4 次尝试。仅 open_upstream 建连/发送阶段的 TransportError、HTTP 429 或 5xx 可重试。等待 max(base × 2^attempt, retry_after)，默认 base=0.5 秒，因此无 Retry-After 时为 0.5 / 1 / 2 秒。Retry-After 仅按数值秒解析，或取 JSON error.metadata.retry_after_seconds；非有限/负值归零，最大 60 秒。HTTP 日期形式不会解析；读取错误响应体失败时等待信息归零。

收到 200 且 Content-Type 包含 text/event-stream 后，立即离开重试范围。此后读取断连即使还没收到首文本也不重试。200 非 SSE 是协议错误，不重试。401 / 403 或其他非 429 的 4xx 不重试。httpx 连接超时 15 秒，默认读写等超时 120 秒；这不是整个生成请求的总时限。

错误交付

位置 / 原因结果
字段不合法422 INVALID_REQUEST；details 只含字段位置和消息。
模型 / 模板 / 变量400 UNKNOWN_MODEL、404 PROMPT_NOT_FOUND、400 INVALID_PROMPT_VARIABLES。
密钥未配置 / 本地限流503 NOT_CONFIGURED；429 RATE_LIMITED 并带 Retry-After: 60。
上游 429 耗尽503 UPSTREAM_RATE_LIMITED（不是本地 429）。
上游鉴权 / 普通失败502 UPSTREAM_AUTH_ERROR / UPSTREAM_ERROR；连接超时耗尽为 504 UPSTREAM_TIMEOUT。
消费阶段502 UPSTREAM_INTERRUPTED、UPSTREAM_PROTOCOL_ERROR、UPSTREAM_TRUNCATED、EMPTY_OUTPUT 或 INVALID_STRUCTURED_OUTPUT。

响应头尚未发送时，以上错误为 HTTP JSON error。stream=true 且已开始下游响应时，消费阶段错误发 SSE event: error，HTTP 通常仍为 200，不再发 done。普通流可能已交付部分文本，结构化流校验失败前不会交付文本。

Usage：统计的是上游报告，不是估算

每个事件用 raw_usage.update(usage) 浅合并，较新的同名字段覆盖旧值，保留 usage_raw。usage_available = bool(raw_usage)，缺失数值按 0；不能把 0 解释为确定免费，也没有本地 tokenizer 估算或跨重试用量汇总。

统计量边界
Responses input_tokens原始 input_tokens；cached_input_tokens 取 input_tokens_details.cached_tokens，不额外加到 input_tokens。
Messages input_tokens原始 input_tokens + cache_read_input_tokens + cache_creation_input_tokens；缓存读取和缓存写入单列保留。
total_tokens统一后的 input_tokens + output_tokens；reasoning_tokens 不再额外加到 total。
reasoning_tokens取 output_tokens_details.reasoning_tokens，否则 thinking_tokens，否则 0。

观测与时间

state 包含 request_id、model、stream、ttft_ms、attempts、status、usage、usage_raw，错误时附 error_code。record 将 latency_ms 算出后写服务日志、内存 deque(maxlen=100)，同步追加本地 metrics.jsonl。文件写失败只记录异常，内存与服务日志保留；这里没有数据库或异步指标管道。

正常 generate 路径：计时从进入函数、创建 state 开始；TTFT 直到首个非空文本块才记录，包含前置处理、重试等待与上游等待。latency 到关闭上游之后、记录动作开始时截止，因此不包含 JSONL 写入耗时、最终 done 编码或客户端接收完成。取消消费时尽力关闭上游并记录 cancelled；拿到上游前发生的 APIError 记录 error。

字段校验错误发生在 generate 之前，单独创建记录：model=None、attempts=0、ttft_ms=None，usage 为空；其 latency 仅覆盖异常处理器里的记录准备时间，不能与正常生成耗时等同。未观察到文本时 TTFT 保持 null。
